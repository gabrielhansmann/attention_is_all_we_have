# 0006 — Load Excel as raw relational tables; chunk PDFs per page with real citations

> Date: 2026-10-10 · Status: accepted

## Context

Opening the provided data changed two assumptions in the earlier docs:

- The "OptionList" PDFs are German sales catalogs (spec tables, equipment tables with ■/□ marks
  and prices, some prose), not clean option listings.
- The feedback spreadsheets carry far more structure than the `finding` table holds: country,
  engine type, feedback type, and a three-level category label. The customer-study workbook is a
  cross-tab, not a flat table, and the sales workbook is tiny.

## Decision

1. **Load every Excel file as raw rows first**, keeping the original columns plus sheet and
   row/cell: `feedback_raw` (comment embedded), `sales_volume`, `study_response`. `finding` rows
   are derived later by the agents and point back to these rows. Counts and filters run in SQL;
   only comments are searched by meaning.
2. **Chunk PDFs per page at headings** (≤ ~1,800 chars), store `page` + verbatim text, embed with
   OpenAI `text-embedding-3-small`. A citation is always `file + page + quote` taken from the
   retrieved row, never generated by the model.
3. **Do not trust flattened equipment tables for variant availability.** The answer prompt tells the
   model to say a table needs checking rather than map ■/□ to a model. Table-aware extraction is
   deferred.
4. **Loaders live in `ingest/`**, are idempotent, and read `SUPABASE_DB_URL` (direct connection) and
   `OPENAI_API_KEY` from `.env`. They use autocommit so each transaction block really commits.
5. **Raw BMW files stay out of git** (`data/` is gitignored).

## Consequences

- Reuses the existing `Vfc` category labels as a candidate first level of the taxonomy.
- `G68` (Chinese 5 Series variant) appears in the studies and sales data (`G60_G68` sheet); the
  ontology must handle it.
- Study cells have no respondent counts, so they cannot carry a sample size.
- Open items: merge tiny PDF chunks, build the Tier 1 `option` extraction, derive `findings`,
  verify study values against the workbook, and migrate the pending chat tables (decision 0005).
